# Exam Hub Blueprint — how we build a prep site for each exam

> Companion to [PLAN.md](../PLAN.md) (Pillar 3: Learn) and [research/exams.md](../research/exams.md).
> The goal: after the first hub is built, every additional exam hub is **configuration + content,
> not a new website**. One platform, one codebase, one template, N exams.

---

## 0. Core principle

A hub is not a separate website. It is:

```
Hub = exam config (YAML) + content (lessons, questions) + shared engine (UI, scoring, SEO)
```

The engine (question player, timer, scoring, mock test runner, review mode, SEO skeleton) is
written once. Each exam contributes:

1. **`/config/exams/<exam>.yaml`** — structure, timing, scoring rules, adaptive logic, fee info, dates
2. **Content** — lessons (MDX), question bank (DB), mock tests, study plans
3. **Deltas** — only the genuinely unique UI pieces (e.g. speaking recorder for IELTS, Desmos-style
   calculator for SAT math, Chinese-character drills for CSCA)

Your in-progress **SAT site becomes the engine's first implementation** — build it as the template,
not as a one-off.

## 1. Anatomy of a hub — the standard layers

### A. Info layer (free, SEO engine)
- **Hub home:** what the exam is, key-facts card (format, duration, cost, dates, validity),
  links into practice, CTA to free diagnostic test
- **Exam guide pages:** section-by-section breakdown, question types, scoring explained
- **Facts pages (programmatic):** `/sat/test-dates-2027`, `/ielts/fees-by-country`,
  `/sat/score-percentiles` — auto-generated from config/DB, refreshed each cycle
- **Score-to-university pages:** "Which universities accept IELTS 6.5?" — generated from our
  university directory (this cross-links the Academy with Pillar 1 and is our unique SEO moat)

### B. Learn layer (free core, premium depth)
- Lessons per section/topic (MDX, with examples and worked questions)
- Strategy guides (time management, elimination tactics, template answers)
- Study plans generated by target score + weeks available → pulls lessons/questions in order

### C. Practice layer (premium-gated beyond a free quota)
- **Question bank:** tagged by section → topic → difficulty; explanations on every question
- **Mock test runner:** timed, sectioned, exam-accurate scoring; adaptive where the real exam is
- **Score tools:** score calculator, percentile tables, concordance (ACT↔SAT, DET↔IELTS, old↔new GMAT)
- **Drill trainers:** vocabulary spaced repetition (IELTS/GRE/CSCA-Chinese), timing drills, error-log

### D. Convert layer (monetization)
- Free diagnostic test → results page shows weak topics → study plan → premium upsell
- Premium: unlimited mocks, full question bank, AI essay/speech feedback, saved progress analytics

## 2. The exam config — what "one exam" means in data

Example (abridged) for SAT:

```yaml
id: sat
name: Digital SAT
owner: College Board
sections:
  - id: rw1
    label: Reading & Writing Module 1
    duration_min: 32
    question_count: 27
    topics: [craft-structure, info-ideas, standard-english-conventions, expression-of-ideas]
  - id: rw2   # adaptive: difficulty selected by rw1 performance
  - id: math1
  - id: math2
scoring:
  scale: [400, 1600]
  per_section: [200, 800]
  method: module-adaptive-conversion   # engine reads official concordance tables
adaptive:
  type: module-stage        # rw2/math2 difficulty depends on rw1/math1 correctness
tools: [desmos-calculator, reference-sheet]
fees: { us: 68, international: 111, currency: USD }
dates_source: collegeboard      # refreshed by ingestion pipeline
validity: none
```

Everything the generic engine needs to *run* an exam accurately lives in this file. Adding an exam
starts with writing its config from the research brief — a 1-day task per exam.

## 3. Shared engine components (build once)

| Component | What it does | Notes |
|---|---|---|
| **Question renderer** | MCQ, multi-select, numeric entry, drag/drop, typed response, essay box, audio player | Cover all exam formats |
| **Test session runner** | Timer, section flow, per-section review rules, "one answer edit" (GMAT), break handling | Rules come from config |
| **Scoring engine** | Raw → scaled score via config; module-adaptive next-difficulty selection; IRT optional later | Official concordance tables stored as data |
| **AI graders** | Essay/SOP scoring vs rubric; speaking responses (record → transcribe → score); writing tasks for IELTS/TOEFL/DET/PTE/CSCA-Chinese | Rubric lives in config per exam |
| **Review & analytics** | Per-topic accuracy, time-per-question, weak-topic detection → feeds study plan | Powers the free diagnostic funnel |
| **Study plan generator** | Target score + weeks available → weekly schedule of lessons + sets + mocks | One algorithm, per-exam weightings |
| **SEO skeleton** | Programmatic page builder from config + DB (dates, fees, percentiles, score→university) | SSRed, schema.org markup |
| **Progress sync** | User profile: scores, attempts, weak topics shared across hubs and into the application tracker | Academy talks to the rest of the platform |

## 4. Data model (shared, exam-agnostic)

- `exams` (id, name, config YAML, fee data, dates)
- `sections`, `topics` (tree per exam)
- `questions` (exam, section, topic, difficulty 1–5, type, stem, options JSON, answer, explanation,
  source: original|adapted|official, quality_status: draft|reviewed|verified)
- `mock_tests` (exam, structure JSON, question sets, scoring profile)
- `lessons` (exam, topic, MDX body, reading level, related questions)
- `study_plans` (user, target score, weeks, generated schedule)
- `attempts` (user, question/mock, answers, timing, scaled result)
- `score_requirements` (exam, score band → university/program links) — the Academy↔Directory bridge

## 5. Content pipeline (solo founder + AI — the real bottleneck)

Per exam, target **launch volume**: 40–60 lessons · 800–1,500 questions · 2–4 full mocks ·
10–20 strategy/SEO articles. Realistic with the pipeline below: **2–3 weeks per hub** after the
template exists.

1. **Collect sources:** official syllabus, sample/released questions, fee & date pages → stored in
   `research/exams/` per exam (research brief is the seed).
2. **AI-draft lessons** from the syllabus, section by section → you review for accuracy
   (exam-experienced reviewers later; mentors can be paid to review — ties into Pillar 7).
3. **Question generation:** AI generates by topic × difficulty from templates → each question gets
   an explanation → you (or a reviewer) validate a sample; every question carries
   `quality_status`. Never publish unreviewed questions — wrong answers destroy trust.
4. **Mocks:** assemble from the bank following the config structure; calibrate scoring against
   official concordance data.
5. **SEO article pass:** keyword map per exam (search patterns: "sat test dates 2027",
   "ielts 6.5 universities", "is 1300 a good sat score", "csca math syllabus") → articles +
   programmatic pages.
6. **Update cycle:** before every test session — refresh dates/fees from the ingestion pipeline;
   annually — syllabus/format changes (the research briefs list recent format changes per exam).

**Licensing rules:** never republish official copyrighted questions; link out or embed where
officially permitted; generate original questions "in the style of"; use trademarks (SAT®, IELTS®)
only nominatively with disclaimers.

## 6. Free vs premium gating (standard across hubs)

| Free | Premium |
|---|---|
| All info/guide pages, programmatic facts pages | Full question bank & unlimited mocks |
| 1 diagnostic test + limited weekly practice set | AI essay/speaking feedback (rubric-scored) |
| Basic score calculator & concordance | Generated study plans + progress analytics |
| All lessons (SEO) | Advanced drills, error-log insights, CSCA Chinese trainers |

---

## 7. Build order (per hub)

1. Write exam config from the research brief (1 day)
2. Hub pages + programmatic SEO skeleton (2–3 days, mostly automatic)
3. Lessons drafted → reviewed (3–5 days)
4. Question bank seeded → validated (5–8 days)
5. Mocks assembled + scoring calibrated (2–3 days)
6. Score tools + score→university cross-links (1–2 days)
7. Study plan weighting + premium gating (1–2 days)
8. Pre-session refresh hooks (dates/fees) (½ day)

**First hub (SAT) = template build: 3–4 weeks.** Every hub after: **1.5–3 weeks** depending on
unique task types (speaking graders for IELTS/TOEFL/DET/PTE add ~1 week the first time they're
needed; CSCA's Chinese-language modules add content work but reuse the MCQ engine).

## 8. Per-exam deltas (what is NOT generic)

| Exam | Unique engine/content needs |
|---|---|
| **SAT** | Module-adaptive scoring, Desmos-style calculator, R&W question types |
| **ACT** | Enhanced ACT format (Science optional), pacing drills |
| **IELTS** | Writing Task 1 (graph description) + Task 2 rubric grader, speaking recorder + band feedback, One Skill Retake practice |
| **TOEFL** | Academic-lecture audio, integrated writing, speaking templates |
| **DET** | At-home question types (C-test, listen-and-type, interactive reading), 1-hour mock format |
| **PTE** | 20 integrated task types, AI-scored speaking (Read Aloud, Repeat Sentence) |
| **CSCA** | Chinese-language modules (character/vocab/reading drills), English-or-Chinese MCQ engine, remote-proctoring tech-prep guide |
| **GRE / GMAT** | Quant + verbal adaptive practice, Data Insights (GMAT), AWA grader |
| **AP** | Per-subject hubs (config per subject), FRQ grading |

## 9. Recommended launch sequence (ties to PLAN.md Phase 2)

1. **SAT** — you're already building it; structure it as the template per this blueprint
2. **IELTS** — biggest global demand; introduces writing/speaking AI graders (reused by TOEFL/DET/PTE later)
3. **TOEFL** — reuses IELTS graders with new rubrics; wins the US/Canada segment
4. **DET** — small unique set; growth market
5. **CSCA** — greenfield SEO; schedule when the China corridor push starts (Tier 1.5)
